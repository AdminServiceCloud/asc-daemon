# 🤖 MCP-сервер демона

## 📌 Описание

`asc mcp serve` — локальный сервер [Model Context Protocol](https://modelcontextprotocol.io/)
для AI-клиентов. Он работает через стандартные ввод и вывод, а все операции
управления передаёт запущенному ASC daemon через локальный Unix-сокет.

Права определяются UID, который ядро передаёт daemon через `SO_PEERCRED`.
В MCP-протоколе нет параметров пользователя, UID, токена или роли: обычный
пользователь видит и изменяет только свои приложения, а root-процесс MCP —
все. `sudo asc mcp serve` следует запускать только когда действительно нужен
полный доступ.

## 🎯 Сценарии

- Разработчик подключает Codex, Claude Code или другой stdio MCP-клиент и
  управляет своими приложениями без добавления в группу `docker`.
- Администратор запускает ту же команду от root для работы со всеми
  приложениями хоста.
- AI читает состояние и логи, устанавливает или обновляет приложения,
  меняет валидируемые схемой настройки и работает с бекапами.

## 🏗️ Техническое решение

### Инструменты

| Tool | Действие | Подсказка MCP |
|---|---|---|
| `system_info`, `metrics_get` | метрики daemon и приложений | только чтение |
| `app_list`, `app_info`, `logs_read`, `app_settings_get` | данные приложения | только чтение |
| `app_install`, `app_upgrade`, `app_control`, `app_settings_update` | управление приложениями | изменение |
| `backup_list`, `backup_create`, `backup_restore`, `backup_prune` | бекапы | restore разрушителен |
| `app_remove`, `exec_command` | удаление и команды хоста | разрушительные |

На каждом вызове daemon заново разрешает ссылку на приложение. Чужое и
несуществующее приложения дают одинаковую ошибку `not found`, поэтому владелец
не раскрывается. Разрушительные инструменты помечены MCP-аннотациями; клиент
должен запросить подтверждение в соответствии со своей политикой.

`exec_command` намеренно запускается MCP-процессом, а не root-daemon. Поэтому
команда получает фактический UID `asc mcp serve`. Используется `/bin/sh -lc`,
timeout по умолчанию — 60 секунд (максимум 300), stdout и stderr ограничены
1 МиБ каждый.

### Подключение MCP-клиента

Требования:

- `asc` установлен и доступен в `PATH` процесса клиента.
- daemon запущен и доступен: команда `asc status` должна завершаться успешно.
- Пользователь клиента может подключиться к Unix-сокету ASC. Сокет намеренно
  доступен для подключения всем, однако daemon проверяет UID процесса ядром
  на каждом запросе.

Конфигурация stdio для Codex-совместимого клиента:

```json
{
  "mcp_servers": {
    "asc": {
      "command": "asc",
      "args": ["mcp", "serve"]
    }
  }
}
```

Обычный запуск клиента даёт доступ только к приложениям его пользователя. Для
административной сессии, которой осознанно нужны все приложения, настройте
команду `sudo` с аргументами `asc`, `mcp`, `serve`; non-interactive sudo
настраивается по политике безопасности хоста.

Для Claude Code:

```bash
claude mcp add asc -- asc mcp serve
```

При ошибке подключения сначала выполните `asc status`, затем проверьте сервис
daemon и путь к сокету в конфигурации. Если `asc` не найден, установите ASC
или укажите абсолютный путь в конфигурации клиента. Не выдавайте root-доступ
лишь для доступа к приложению пользователя: сначала убедитесь, что приложение
установлено под правильным UID.
