# 🔐 WireGuard (демон)

> 🌍 **Язык:** Русский · [🇬🇧 English version](../english/wireguard.md)

## 📌 Описание

Модуль `wireguard` ставит [WireGuard](https://www.wireguard.com/) на ноду и управляет туннелями: VPN-сервер для команды, связь между двумя серверами (site-to-site) или клиентский туннель к чужому VPN. Он создаёт интерфейсы, выдаёт пирам адреса и ключи, собирает готовые клиентские конфиги, показывает живые рукопожатия и трафик и **импортирует готовый `.conf`** — свой или выданный провайдером.

Источник правды — обычный `/etc/wireguard/<имя>.conf`, который читает `wg-quick`: туннель работает и без демона, и его можно передать другим инструментам. Демон управляет файлами с его меткой (`# Managed by ASC`); остальные `*.conf` в каталоге показываются, их можно прочитать (ключи скрыты) и включить или выключить, но не редактируются — импортируйте файл, чтобы взять его под управление. Всё работает автономно через `asc wireguard …`; платформа AdminService.Cloud использует тот же API ([🧩 node-modules](../../../asc-platform/docs/features/node-modules.md)). Команде нужен работающий демон. WireGuard управляет только системный демон (root).

## 🎯 Сценарии

- 🧰 `sudo asc wireguard install` ставит `wireguard-tools` (apt / dnf), лог идёт потоком.
- 🛰️ `sudo asc wireguard add wg0 --address 10.8.0.1/24 --port 51820 --endpoint vpn.example.com --nat` создаёт VPN-сервер: новая пара ключей, интерфейс поднят сейчас и при загрузке, а с `--nat` хост выпускает подсеть VPN в интернет через маскарад.
- 📱 `sudo asc wireguard peer add wg0 phone` берёт следующий свободный адрес подсети, генерирует ключи и pre-shared key и печатает клиентский конфиг (приватный ключ показывается **один раз**, демон хранит только публичный). Платформа показывает его текстом, файлом и QR-кодом.
- 🧭 `--routes` задаёт, что клиент отправляет в туннель, то есть его **AllowedIPs**: `full` (`0.0.0.0/0, ::/0`, всё), `subnet` (только сеть VPN, по умолчанию) или список вроде `10.8.0.0/24,192.168.10.0/24`. На стороне сервера `peer set wg0 <ключ> --allowed-ips 10.8.0.2/32,192.168.50.0/24` делает так, что пир ещё и обслуживает сеть за ним (site-to-site).
- 📥 `sudo asc wireguard import office.conf` принимает готовый файл. Подходят и **серверный** (с `ListenPort` и пирами), и **клиентский** (один пир с `Endpoint` и `AllowedIPs = 0.0.0.0/0`): интерфейс проверяется, переписывается с меткой ASC, ключи сохраняются, а с `--start` туннель сразу поднимается. Имя по умолчанию — имя файла.
- 🔁 `peer set wg0 <ключ> --disable` отключает потерянный телефон, не забывая запись; `--enable` возвращает. `peer remove` удаляет её.
- 📊 `asc wireguard status` показывает по интерфейсам пиров с последним рукопожатием и трафиком. `asc wireguard show wg0` печатает файл интерфейса со скрытыми ключами; `up` / `down` включают и выключают туннель (и его запуск при загрузке). Панель делает то же из списка: клик по туннелю показывает его конфигурацию и переключатель, клик по пиру — его данные и переключатель.
- ⚠️ Файл с `PostUp` / `PostDown` / `PreUp` / `PreDown` выполняет команды от root; он отклоняется, пока не передан `--accept-hooks`. `SaveConfig = true` отбрасывается (иначе `wg-quick` перезаписал бы файл).

## 🏗️ Техническое решение

Код: `src/daemon/wireguard/` — `model.rs` (интерфейс, пир, проверки, выдача адресов), `conf.rs` (разбор и рендер `.conf`, клиентский конфиг), `tool.rs` (обёртка над `wg` / `wg-quick` / systemd за трейтом, разбор `wg show dump`), `mod.rs` (менеджер).

### Установка и удаление
`install` вызывает пакетный менеджер (apt, dnf или yum) для `wireguard-tools`; модуль ядра входит в Linux 5.6+ (для старых нужен `wireguard-dkms`, демон его не ставит и говорит об этом). `uninstall` останавливает управляемые интерфейсы и удаляет пакет; `--purge` удаляет и управляемые `.conf` (в них приватные ключи).

### Файл
```
# Managed by ASC. Edit with `asc wireguard` or the panel; manual edits are kept
# only while the format below stays intact.
[Interface]
# asc:endpoint = vpn.example.com
# asc:client-dns = 1.1.1.1
# asc:masquerade
PrivateKey = …
Address = 10.8.0.1/24
ListenPort = 51820
PostUp = … # asc:nat
PostDown = … # asc:nat

[Peer]
# asc:name = phone
PublicKey = …
PresharedKey = …
AllowedIPs = 10.8.0.2/32
PersistentKeepalive = 25
```
- Комментарии `# asc:` хранят то, для чего в WireGuard нет поля: публичный адрес и DNS для клиентских конфигов, имя пира, переключатель NAT. `wg` и `wg-quick` комментарии игнорируют.
- DNS для **клиентов** намеренно не пишется строкой `DNS =`: на сервере `wg-quick` применил бы её к самому серверу (через `resolvconf`) и изменил бы разрешение имён на хосте. Настоящий `DNS =` сохраняется только там, где он на месте, — в импортированном клиентском файле, то есть в туннеле для трафика самого хоста.
- **Отключённый** пир хранится блоком `[Peer]`, каждая строка которого начинается с `#asc:off `; он не загружается.
- При включённом NAT демон пишет две строки хуков с пометкой `# asc:nat`: `net.ipv4.ip_forward=1` и собственную таблицу nftables `ip asc_wg_<имя>` с одним правилом `masquerade` для подсети VPN. При выключении NAT они удаляются; чужие хуки не трогаются. Модуль файрвола ([🛡️ firewall](firewall.md)) и эта таблица независимы и друг друга не перезаписывают.
- Файл пишется атомарно с правами `0600` и проверяется `wg-quick strip` перед использованием.

### Применение изменений
- **Пиры и порт** меняются в работающем туннеле без обрыва: `wg syncconf`.
- **Адреса, MTU, DNS, таблица маршрутов, хуки, NAT** требуют пересборки интерфейса `wg-quick`: демон перезапускает его (короткий разрыв).
- Если новый файл отклонён, возвращается прежний, интерфейс восстанавливается.
- Интерфейс поднимается и включается при загрузке через `systemctl enable --now wg-quick@<имя>` (`wg-quick up`, если systemd нет). Если `wg-quick` отказался от файла, юнит не остаётся включённым, а в ошибке — последние строки его журнала.

### Адреса и AllowedIPs
- Новый пир получает следующий свободный адрес сети интерфейса (`/32` для IPv4, `/128` для IPv6), минуя адрес самого сервера и всё, что уже есть в AllowedIPs пиров. Адреса можно задать и самому.
- **AllowedIPs пира на сервере** — адреса и сети, которые маршрутизируются на этого пира; демон проверяет, что это корректные CIDR и что один адрес хоста не занят двумя пирами одного интерфейса.
- **AllowedIPs клиентского конфига** — то, что клиент отправляет в туннель; это параметр конфига (`full`, `subnet` или список), он не хранится.
- `Address` клиента — адреса хоста пира.

### Импорт
`import` разбирает текст тем же парсером, что и управляемые файлы, поэтому файл демона и чужой файл идут одним путём:
- обязательно: `[Interface]` с корректным `PrivateKey`; у каждого пира есть `PublicKey`; ключи — 32 байта в base64; адреса, `AllowedIPs`, `Endpoint`, порты и `MTU` проверяются;
- сохраняется: `Address`, `ListenPort`, `DNS`, `MTU`, `Table`, `FwMark`, пиры с `PresharedKey`, `Endpoint`, `PersistentKeepalive` и хуки (только с подтверждением);
- отбрасывается с предупреждением в ответе: `SaveConfig`, неизвестные ключи;
- интерфейс с таким именем уже есть — отказ, если не передан `--overwrite`; старый файл сохраняется как `<имя>.conf.asc-bak`.

### Ошибки
Некорректный ввод → `INVALID_ARGUMENT`; WireGuard не установлен, интерфейс не под управлением ASC, имя или порт заняты → `FAILED_PRECONDITION`; неизвестный интерфейс или пир → `NOT_FOUND`.

### API (`WireguardService`)
- `GetWireguard` — установлен ли, версия, все управляемые интерфейсы с пирами и живыми данными (время рукопожатия, endpoint, байты), неуправляемые (имя и состояние), основной адрес ноды (подсказка для публичного endpoint). Приватные и pre-shared ключи **никогда** не возвращаются; pre-shared ключ есть только внутри клиентского конфига.
- `GetWireguardInterfaceConfig` — файл интерфейса для чтения, приватные и pre-shared ключи заменены на `(hidden)`. Работает и для неуправляемых файлов.
- `InstallWireguardStream` (log | done | error), `UninstallWireguard`.
- `UpsertWireguardInterface` — создать или изменить: имя, порт, адреса, DNS клиентов (и собственный `dns` хоста для клиентского туннеля), MTU, публичный endpoint, NAT.
- `RemoveWireguardInterface`, `SetWireguardInterfaceState` (поднять и включить при загрузке / опустить и выключить; и для неуправляемых файлов).
- `ImportWireguardConfig` — текст, `overwrite`, `accept_hooks`, `start`; возвращает состояние и предупреждения.
- `AddWireguardPeer` — возвращает клиентский конфиг (с приватным ключом, если его сгенерировал демон); `UpdateWireguardPeer`, `RemoveWireguardPeer`.
- `GetWireguardPeerConfig` — клиентский конфиг существующего пира с заглушкой `<PRIVATE_KEY>` (демон его не хранит).

Capability: `wireguard`. REST-маршруты `/v1/wireguard` повторяют вызовы для CLI.

### CLI
`asc wireguard status | install | uninstall | add | set | remove | up | down | show | import | peer add | peer set | peer remove | peer config`. Строки идут через систему переводов (EN, RU). Справочник команд: <https://docs.adminservice.cloud/ru/commands/wireguard>.
