# 🔗 Подключение к платформе

> 🌍 **Язык:** Русский · [🇬🇧 English version](../english/platform.md)

## 📌 Описание

Демон полностью автономен: всё работает через CLI и локальный API, без учётной
записи в платформе. Подключение к AdminService.Cloud необязательно и добавляет
сверху панель управления, AI-ассистента, команды и роли.

Связь устанавливается **одноразовым токеном регистрации**, который выдаётся в
панели. Токен можно передать сразу установщику либо позже — командой
`asc connect`.

## 🎯 Сценарии

- Оператор копирует команду установки из панели и выполняет её на чистом
  сервере: демон ставится и регистрирует ноду за один шаг.
- Платформа сама заходит по SSH, ставит демон и передаёт тот же токен.
- Ноду, установленную раньше без платформы, подключают позже:
  `sudo asc connect <токен>`.
- Регистрация не прошла, потому что платформа была недоступна: демон всё равно
  работает локально, а оператор повторяет попытку через `asc connect`.

## 🏗️ Техническое решение

### Команда установки

```bash
curl -fsSL https://raw.githubusercontent.com/AdminServiceCloud/asc-daemon/main/install.sh \
  | sudo bash -s -- --silent --token <ТОКЕН> --url https://adminservice.cloud
```

| Опция | Значение |
|---|---|
| `--silent` | Принять настройки по умолчанию и ничего не спрашивать — режим, который использует платформа |
| `--token <ТОКЕН>` | Одноразовый токен регистрации; привязывает ноду к выдавшей его организации |
| `--url <URL>` | Базовый URL платформы, по умолчанию `https://adminservice.cloud` |

Принимаются обе формы: `--token <значение>` и `--token=<значение>`. Токен
проверяется до использования и может содержать только буквы, цифры, `-` и `_`.
Отдельный `--url` отклоняется: без токена регистрировать нечего.

`install.sh` пробрасывает опции в `asc-updater install`, который сначала
устанавливает демон, а регистрирует уже после.

### `asc connect`

```bash
sudo asc connect <ТОКЕН> [--url https://adminservice.cloud]
```

Требует root: команда пишет файлы, принадлежащие root. Она сохраняет токен,
запоминает URL платформы и вызывает endpoint регистрации — тот же путь, что и у
установщика, но без переустановки. `asc status` показывает платформу и id ноды
либо сообщает, что нода не подключена.

### Где что хранится

| Что | Где | Доступ |
|---|---|---|
| Токен регистрации | `/etc/asc/platform.token` | `0600`, только root |
| URL платформы, id ноды, время регистрации | секция `[platform]` в `/etc/asc/config.toml` | `0644` |

Разделение следует правилу, которое уже записано в самом конфиге: секреты
никогда не лежат в `config.toml` — он намеренно доступен на чтение всем, чтобы
любой пользователь мог посмотреть настройки демона.

```toml
[platform]
url = "https://adminservice.cloud"
node_id = "0e2f…"
registered_at = "2026-08-20T09:31:04Z"
```

### Запрос регистрации

Демон отправляет один запрос на публичный bootstrap-endpoint платформы:

```
POST <url>/bootstrap/asc.node.v1.BootstrapService/RegisterNode
Content-Type: application/json

{"token":"…","hostname":"…","primaryIp":"…","os":"…","arch":"x86_64","daemonVersion":"0.10.0"}
```

Тело уходит через stdin, а не аргументом командной строки, поэтому токен не
виден в выводе `ps`. Платформа гасит токен — он работает ровно один раз — и
отвечает идентификаторами ноды и организации.

URL с `http://` разрешён для локальной разработки, но выводится предупреждение:
токен пойдёт по сети незашифрованным.

### Обработка ошибок

Регистрация никогда не роняет установку. Если платформа недоступна, установщик
печатает предупреждение и завершается успешно: демон установлен и работает
локально, а `asc connect` повторит попытку в удобный момент.

### Что пока не реализовано

Постоянного канала с платформой нет. Зарегистрированная нода один раз сообщает
о себе и на этом останавливается: heartbeat не отправляется, и панель не
показывает её как online. Команды из панели, стрим логов и метрики появятся
вместе с туннелем платформы (задача NODE-002 на стороне платформы).

## 🔗 Связанные задачи

DMN-058 в [ROADMAP](../../../asc-platform/ROADMAP.md); на стороне платформы —
NODE-001 (реестр нод и токены регистрации) и NODE-002 (канал платформа ↔ демон).
